This page is the exhaustive list. It enumerates every pre-built [SEM entity](/embodiment/sem-protocol/) that ships in the Maxim component library — genre tags, sensors, affordances, and failure modes — read directly from the registry files. It is the companion to the [component library](/embodiment/component-library/) page, which explains how the registry, genre gating, and the ComponentIndex discovery layer work; that page is the "how", this page is the "what". Maxim is a bio-inspired cognitive architecture (`pip install pymaxim`, `import maxim`), and these components are the reusable furniture its cognition acts on.

## The count, derived

The catalog below holds **{data.count} components** across {data.categories.length} categories, generated from **{data.source_label}** by [`scripts/build-components.mjs`](https://github.com/dennys246/Maxim-web/blob/main/scripts/build-components.mjs) in this site's repo. The script applies the same rule as the engine's `ComponentRegistry`: a YAML file under [`src/maxim/_data/components/`](https://github.com/dennys246/Maxim/tree/v1.1.0/src/maxim/_data/components) is a component if and only if it carries a `component:` header. The {skipped} files in `archetypes/` (`humanoid`, `quadruped`, `avian`, `serpentine`, `machine`, `vehicle`, `environmental`) have no such header — they are body-plan scaffolds other components inherit from — so both the runtime registry and this page skip them. The generated set was checked against `ComponentRegistry().list_refs()` on the installed 1.1.0 wheel and matches it exactly.

**Why older numbers differ.** Three hand-maintained totals have circulated: the engine's user doc says **72**, the retired interactive catalog said **73**, and an earlier version of this page counted **81** files. None was wrong about the files it looked at; they disagreed about what to count. The curated docs listed a stable subset and left out experiment fixtures — the `warmth_*` items tagged `exp42`, the `infant_humanoid*` and `infant_operant` body variants used by the [Cradle](/research/cradle/) and hunger-relief experiments, the `cradle_*` scene objects — and each snapshot was taken at a different commit as fixtures were added. The number above is not curated: it is every file the registry indexes, at the wheel version named. Regenerate it with `pnpm build:components -- --source <registry dir> --label "<version>"` whenever the engine changes; the script refuses duplicate refs and reports what it skipped, so a wrong count cannot be typed in.

## Catalog

Search matches names, synonyms (the same aliases the [ComponentIndex](/embodiment/component-library/#discovery-the-componentindex) resolves), tags, sensors, affordances, failure modes, and descriptions. Genre `neutral` means the component carries no genre tag and is available in every campaign. Components that `extends` a parent list only what they declare themselves; the parent's sensors and affordances are inherited at load time.

## Keeping this current

The files win. The canonical live source is [`src/maxim/_data/components/`](https://github.com/dennys246/Maxim/tree/main/src/maxim/_data/components) on GitHub (the links on each card point at the `v1.1.0` tag this catalog was generated from). To enumerate the registry yourself, `maxim.create.templates()` returns the live grouping by category from whatever pymaxim you have installed, including anything you dropped into `~/.maxim/components/`.
